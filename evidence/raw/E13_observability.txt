== alert rule file (deploy/observability/prometheus/alerts.yml)
groups:
  - name: cogent
    rules:
      # The one alert: more than a quarter of the agent's operations failed over the last 24 hours.
      # An operation is a fetch of one document, one tracker page, one entry rebuild, one table load, one join inference ...
      # (cogent_agent_operations_total{outcome="error"}); a source that is down, a blocked site or a broken parser shows up here.
      - alert: CogentAgentFailureRateHigh
        expr: |
          (sum(increase(cogent_agent_operations_total{outcome="error"}[24h])) or vector(0))
            / clamp_min(sum(increase(cogent_agent_operations_total[24h])), 1) > 0.25
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "cogent agent: {{ $value | humanizePercentage }} of operations failed in the last 24 h"
          description: >-
            More than 25% of the daily agent's operations failed. Look at 'Failures by stage' on the Grafana dashboard "cogent: agent and MCP server",
            at the report (logs/report.md) and at <home>/logs/metrics.jsonl for the last run.

# Observability: traces, metrics, dashboard, alert

The daily agent and the MCP server emit **OpenTelemetry traces** and **Prometheus metrics**. A Grafana dashboard and one alert rule ship in `deploy/observability/`.

![Grafana dashboard](img/grafana-dashboard.png)

The screenshot was taken from a real Prometheus and Grafana, fed by `deploy/observability/demo/generate_traffic.py` (see "Reproduce the screenshot"). The traffic is synthetic: a mock web site, a mock Ollama that reports token counts and sometimes invents a column, and an illustrative price. It shows what the panels look like, not how your sources behave.

Code: `src/kg_telemetry.py` (registry, tracing helpers, per-run summary); calls are spread through `kg_agent.py`, `kg_mcp.py`, `kg_llm.py`, `kg_llmjoin.py`, `kg_embed.py`, `kg_tools.py`, `kg_tabledb.py`, `kg_ingest.py` and `kg_daemon.py`.
